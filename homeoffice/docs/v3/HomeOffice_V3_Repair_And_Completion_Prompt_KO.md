# Friendslop HomeOffice V3 — 실제 고장 수리·회의실 중심 재설계·완성 지시서

작성일: 2026-09-15. 대상: `mjayj9/Friendslop_HomeOffice`, PR #1.
기준 소스: `codex/godot-homeoffice-v2` / `e62360fd45e03e15fe7e2371d204dc30ff35c9ae`.

이 문서는 코딩 AI에게 전달할 구현 프롬프트다. 이 파일을 만들었다고 게임을 수정·완성하거나 아래 인수를 통과한 것이 아니다. 마지막의 감사 부록은 확인된 코드 사실, 사용자 보고, 추정, 실행하지 못한 부분을 구분한다. 구현 시작 시 현재 head가 바뀌었는지 다시 확인한다.

## 0. 역할과 최우선 목표

너는 Godot 네트워크 게임 개발자, 게임플레이/물리 엔지니어, Blender 캐릭터 테크니컬 아티스트, 환경 디자이너, 웹 협업/실시간 음성 엔지니어다. 기능 메뉴가 많은 시제품이 아니라 **친구가 실제로 보이고, 움직임·사물·게임·회의가 자연스럽게 작동하는 집과 오피스**를 완성하라.

실제 대상:
- 배포 사이트: https://mjayj9.github.io/Friendslop_HomeOffice/
- PR: https://github.com/mjayj9/Friendslop_HomeOffice/pull/1
- 경험 참고: https://larshurrelb.github.io/friendslop-base/
- 참고 코드: https://github.com/larshurrelb/friendslop-base/

사용자가 보고한 실패를 README의 ‘테스트 통과’ 문구로 반박하지 마라. 플레이어 수=2, 노드 생성 성공, 함수 호출 성공, 다운로드 성공, 씬 파일 존재는 실제 시각·조작·게임성·복원 성공의 대체 증거가 아니다.

진행 우선순위는 **P0 실제 서로 보이는 멀티플레이 → 입력/애니메이션/물리/권위 기반 → 가장 중요한 회의실과 실제 공동작업 → 스포츠·생활·디자인 통합 → 배포·장시간 검증**이다. 완성 기능을 단계 뒤로 보내 범위에서 없애지 마라. 미완료는 미완료로 남기되 그 상태를 제품 완성으로 제출하지 않는다.

이전과 달리 지금 있는 코드를 무조건 폐기해 또 새 시제품을 만들지 마라. 작은 실패 재현과 회귀 테스트를 만든 뒤, 보존할 기능과 교체할 결합을 구분해 구조를 개선한다. 이 단계가 필요한 큰 리팩터링과 양립한다.

- 이전 Q 내려놓기/좌클릭 일반 던지기 대신 R14의 **E 집기/내리기, Q 던지기**를 기본으로 한다.

- ‘총을 마음껏’은 허가된 놀이 공간에서 번거롭게 막히지 않고 쏘게 하는 요구다. 기존 방장 승인/안전 구역을 삭제하라는 요청으로 확대하지 않는다.
- 내장 Yjs/PDF 기능은 보존 가능한 보조 기능이지만 실제 Google/Excel 공동작업의 대체품은 아니다.
- 고정 링크만 추가하고 아무도 없으면 접속 불가능한 버튼을 ‘교실 완료’라고 하지 마라. 15절의 운영 의미를 함께 구현한다.

## 2. 실제 코드·배포 사전 진단

PR과 기본 브랜치, Pages 배포 커밋, 실제 HTML/JS/WASM/PCK/에셋을 비교한다. PR #1이 미병합이라는 이유만으로 main이 배포된다고 추정하지 마라. 감사 시점의 Pages 작업은 PR head를 배포했다. 현재 상태를 다시 확인하라.

`build-info.json`에 commit, dirty 여부, Godot/export templates 버전, protocolVersion, assetVersion, schemaVersion, build time과 핵심 산출물 hash를 생성한다. UI의 작은 버전 표시와 오류 보고에 활용한다. JS/PCK가 서로 다른 빌드면 입장을 멈추고 올바른 새로고침 방법을 안내한다. 사용자의 세계 캐시/저장 파일을 임의 삭제하지 마라.

## 3. P0 — 상대방이 실제로 보이게 고쳐라

다음 경로를 계측하여 어느 단계에서 끊기는지 확인한다.
```
초대 해석 → 실제 다른 사용자와 연결 → hello/버전/세션 확인
→ 호스트 roster → state 수신 → entity 생성 → GLB/Skeleton 로딩
→ world transform 갱신 → 가시성/layer/camera/culling → 실제 화면
```

`participantId`, 지속적인 개인실 슬롯 ID, `peerId`, `worldId`, `sessionEpoch`, 표시 닉네임, `local_player`를 구분한다. 닉네임·같은 로컬 저장소 값으로 모든 아바타를 자기 캐릭터로 판정하지 마라. 재접속 시 옛 노드를 정리하되 새 노드/새 카메라를 함께 지우지 않는다. 생성 상한, 잘못된 epoch, 순서 뒤집힌 welcome/state, 로딩 중 누락 이벤트도 검사한다.

원격 아바타의 GLB 실제 경로·불러오기 오류·크기·원점·좌표축·scene root·Skin·Skeleton·Mesh AABB·visibility·material·render layer·camera cull mask·현재 카메라를 확인한다. 직접 원인은 검사 전 가설로 표기한다. debug marker는 진단에만 사용하며 최종 사람 모델로 대신하지 않는다.

진단 패널은 각 클라이언트의 connection status/role/session, host roster count, received state count/age, instantiated avatar count, loaded model count, per-avatar local/remote flag 및 transform을 보여준다. 미승인 사용자에게 내부 비밀·권한 토큰은 보여주지 않는다.

**P0 통과:** 호스트 A와 B뿐 아니라 C까지 접속해 A↔B, A↔C, B↔C 모두 서로의 실제 몸체·위치·회전·걷기·앉기를 본다. 입장 순서 변경, 같은 닉네임, 독립 브라우저 프로필, 재접속, 모델 로딩 지연, 한 명 퇴장을 시험한다. 마지막에는 서로 다른 두 PC/네트워크에서 수행한다. 인원 카운터·콘솔·단일 스크린샷만으로 통과하지 않는다.

## 4. 구조 리팩터링 — 코드 생성이 게임 로직을 덮지 않게 하라

현재 `assemble_v2.py`는 .txt의 함수를 정규식으로 조합해 world.gd를 만든다. 게임 로직의 단일 원본을 정하고 이 이중화 문제를 먼저 정리한다. Blender/레이아웃/메시/데이터 생성은 유지할 수 있지만 게임 .gd 로직의 문자열 덮어쓰기 생성은 제거하거나 명시적인 전환 절차로 폐기한다. 생성된 world.gd만 고친 뒤 재생성하면 수정이 사라지는 상태를 남기지 마라.

파일 수를 늘리는 것이 아니라 책임/데이터 소유권을 나누어라. 예시:
```
core/SessionController, CommandRouter, WorldState, AuthorityPolicy
network/TransportAdapter, Roster, Replication, Reconnect, HostHandoff
player/PlayerController, AvatarPresenter, AnimationState, CameraRig
interaction/InteractionResolver, PropCapability, Carry/Throw, Seat/Use
sports/BasketballController, FootballController, BallPhysicsProfile
combat/WeaponController, Damage/Respawn, KillMeter, WeaponPermission
meeting/MeetingRoomController, SharedDocumentRegistry, PresentationSurface, Laser
voice/VoiceRouter, SpatialAudio, STTProvider, CaptionRouter, BroadcastController
world/House, Office, Classroom, BroadcastRoom, Yard, PersonalRoomExpansion
persistence/WorldSnapshot, ImportValidator, Migration
web/BrowserBridge, FileIO, ProviderLaunchers, PermissionUI
```
모든 항목을 거대한 singleton이나 전역 Dictionary의 우회 참조로 다시 묶지 마라. Godot가 게임 상태/물리 권위를, JS가 브라우저 미디어/문서 UI를 소유하고, 명시된 명령·이벤트·DTO로 소통한다. 렌더/UI는 상태를 표시하지 호스트 권한을 생성하지 않는다.

일반 명령에는 requestId·actor·sessionEpoch·targetId와 검증된 payload를 사용한다. 결과는 accepted/rejected·reason·stateRevision으로 응답한다. 사격, 점유, 스틸, 문 사용에서 중복 요청을 멱등 처리한다. 플레이어가 보낸 ‘점수/HP/최종 좌표’를 그대로 신뢰하지 않는다.

현재 코드에 이미 있는 저장·Yjs·음성·점유 기능은 characterization test로 보호하면서 한 책임씩 교체한다. 모든 파일을 한 번에 새로 생성해 회귀를 찾지 못하게 하지 마라. PR은 되돌릴 수 있는 단위로 나누고, 사용자 승인 없이 병합·운영 배포·기존 서비스 변경을 수행하지 않는다.

## 5. 남자 GLB·BlenderMCP·애니메이션

Godot는 유지한다. BlenderMCP 포트 9876은 사용자가 제공한 제작 환경 정보다. 현재 도구 목록/읽기 전용 씬 조회로 연결을 확인하며 원격 컨테이너 localhost를 사용자 PC로 간주하지 마라. 기존 .blend를 덮지 않고 새 버전으로 작업한다. 게임이 이 포트를 호출하게 하지 않는다.

저장소에는 `male-rigged.glb`, `male-seated.glb`, `male-lying.glb`, `male-arms.glb`와 다른 남자 모델들이 이미 있다. 현재 어떤 원본에서 파생되었는지 확인하라. 실제 사용자 원본이 없거나 다른 모델이면 **남자 GLB와 별도 리깅/애니메이션 파일 업로드를 요청**한다. 이미 받은 파일을 못 찾았다는 이유로 임의 캐릭터로 교체하지 마라. 우선 남자 한 종류를 제대로 완성한다.

현재 sin(gait)로 일부 본을 돌리는 방식은 최종 애니메이션이 아니다. Blender에서 리깅·weight·root/hips·발/손 기준을 정리하고, 다음 클립과 전이를 제작/리타깃해 Godot의 AnimationTree/BlendSpace 등에 연결한다.

- idle, walk/run 전후좌우, start/stop, turn, crouch, jump/air/land, 계단 이동.
- reach/pickup/carry/drop/throw; 가벼운 책/상자/의자 등 무게별 자세.
- sit_enter/sit_idle/sit_exit, sofa_relax, bed_enter/lie/sleep/wake/bed_exit.
- book_read, marker_write/erase, laptop_work, wall_switch, drawer/door_use.
- aim/fire/reload/shield/block/hit/KO/respawn.
- 농구 dribble/crossover/pass/shot/follow-through/steal.
- 축구 foot_touch/receive/pass/shoot/steal.
- cook/plate/carry_food/eat/clean; 마이크 앞 방송 자세.

원본에 없는 클립은 없다고 명시하고 실제 제작 방법을 기록한다. 서로 다른 자세의 정적 메시를 순간 교체하는 것으로 자연스러운 앉기/취침 완료를 주장하지 마라.

이동은 실제 수평 속도/가속/방향에 맞춰 보행 주기·발 접촉을 조절한다. root motion과 controller 이동을 동시에 더해 이중 이동시키지 않는다. 네트워크 속도 보정과 시각 보간을 분리하며 완전 결정적 물리라고 주장하지 않는다. 손/발 IK와 grip anchor를 적용하고 무기·공·마카의 상대 위치를 맞춘다.

각 클립의 길이/루프/root motion/전이 조건/필수 본/검증 화면을 manifest에 남긴다. A-pose·상체 뒤집힘·발 미끄러짐·손에서 떠 있는 물체·몸 관통을 실제 웹 빌드로 확인한다.

## 6. 공통 입력과 상호작용 — 최신 키 요구 고정

| 입력 | 기본 의미 |
|---|---|
| E | 이동 가능한 사물을 집기; 이미 들었으면 내리기. 빈손일 때 대상별 집기 안내 |
| Q | 들고 있는 사물 던지기. 책·상자·공 등 일반 사물은 좌클릭으로 던지지 않음 |
| 좌클릭 | 손의 도구 사용: 총 발사, 마카 쓰기, 농구 슛 충전/릴리스 등 |
| F | 대상의 기능 사용: 앉기/일어서기, 문/전등, 읽기, 컴퓨터·보드·침대 사용 |
| R | 재장전/명시한 보조 동작. 기능별 UI로 안내 |
| WASD/마우스/Space/Shift/C | 이동·시점·점프·달리기·웅크리기 |
| V/M/Esc | 눌러 말하기/음소거/커서 해제·메뉴 |

이 표는 E를 모든 용도의 ‘interact’로 다시 덮어쓰지 않기 위한 기본안이다. 문 같은 고정 시설은 E 집기가 불가능하다는 표시와 F 기능을 제공한다. 벽·계단·배관까지 들어올리라는 뜻은 아니지만, 책/일반 가구를 성능 핑계로 전부 정적 장식으로 바꾸지 마라.

모든 비구조적 소품은 `CanCarry/CanThrow/CanUse/CanSeat/CanToggle` 등의 명시된 능력을 가진다. 의자·이동 가능한 책상/스탠드는 무게에 따라 느리게/양손으로 들 수 있고, 점유 중에는 안내와 함께 거절한다. 벽스위치/고정등/욕실 설비는 실제 기능을 사용한다. 원문 물건(의자·책상·총·방패·책·마카·상자)은 모두 의미 있는 행동을 가진다.

E/Q/클릭/F의 우선순위는 PLAY/UI_FOCUSED/BUILD/SEATED/SLEEPING/MINIGAME/SPORTS 상태에 따라 하나로 해석한다. 한국어 IME·Docs 입력·채팅 중 이동/발사/점프가 발생하면 불합격. UI에서 키를 소비하면 게임까지 중복 전달하지 않는다. 변경된 키는 안내와 설정/재접속에도 일치해야 한다.

사물 사용은 실제 레이/거리/가림/무게/소유권/권한과 호스트 판정을 거친다. ghost 배치, 회전, 스냅, 문/계단/스폰/타인 자리 보호, 수납, 던진 물건 회수, 동시 점유, 들고 퇴장/삭제 모두 처리한다. 토스트만 표시하는 가짜 사용은 완료가 아니다.

## 7. 물리 재설계와 검증장

Godot 4.x 버전과 물리 백엔드의 웹 지원을 확인한다. 백엔드 이름을 바꾸면 모든 물리가 좋아진다고 생각하지 마라. 실제 문제는 치수, collider, contact 재질, 제어기, authority, tick, 애니메이션 전이가 함께 원인일 수 있다.

한 기준 단위(예: 1 unit=1m)와 공통 PhysicsProfile 리소스를 사용한다. 기존 농구/축구 반지름 `.24/.22`와 림 `.43`은 우선 재검토 대상이다. 반지름/지름·모델/충돌체·플레이어 손/키·백보드/골 센서가 같은 치수 기준인지 측정한다. 현실 경기 수치는 공식 자료로 확인하고, 게임용 조정은 조정값으로 표기한다. 예시 목표 반지름 약 .12m/.11m는 검증할 초기 설계값이지 이미 측정한 결과가 아니다.

렌더링과 고정 물리 tick을 분리하고, sleep·CCD/sweep·속도/힘 상한·질량·마찰·반발·contact margin을 사물별로 정한다. 단일 재질/bounce 값으로 바닥·백보드·림·고무·목재를 모두 처리하지 않는다. 시각용 상세 메시와 정적/볼록 충돌체를 분리한다.

별도 물리 검증장에 평지·계단·경사·문턱·낮은 천장·문·책상·상자 더미·공 낙하·백보드·림을 둔다. 계단은 시각 계단과 검증된 충돌 ramp/step 정책을 조화시키고 순간 전방 두 배 이동 같은 보정의 부작용을 제거한다. 작은 키·달리기·옆걸음·물체를 든 교행·역주행 모두 시험한다.

공 낙하 높이/반발 높이, backboard 입사/반사 속도, spin 변화, 관통·끼임·idle jitter·고속 투척을 로그와 재현 씬으로 남긴다. 농구 질감 개선을 ‘공이 골대로 끌려가는 숨은 힘’으로 해결하지 않는다. assist는 사용자가 인지하는 선택 기능으로 한정한다.

## 8. 총 — 발사 수리·자유사격·체력·킬 게이지

확인된 출발점: 초기 `rounds.tag.phase=ready`, `fire_tag()`는 practice/play만 허용하며 silent return한다. 이 상태 경로, 권한, 장착 상태, 입력, 탄약, cooldown, 총구 막힘을 먼저 진단하고 각각 명확한 거절 사유를 표시한다. 모든 발사 실패를 그 조건 하나로 단정하지 마라.

방장이 무기방/허용 사용자를 승인하면 **별도 숨은 게임 시작 절차 없이 자유사격이 가능한 Practice**로 일관되게 진입하게 한다. 기본 자유사격은 무제한 탄약이며, 좌클릭 유지 시 정의된 cadence로 연사한다. 무제한은 매 프레임 무한 발사 이벤트라는 뜻이 아니다. 발사 빈도 상한·음향/이펙트 pooling·네트워크 rate limit은 유지한다. 제한 탄약/재장전 경기는 별도 선택 모드다.

weapon entry permission, equip, aim, pressed/held/released, cooldown, fire request, shot accepted, hit, damage, KO, respawn을 연결한다. 총구가 벽 안에 있을 때 카메라 레이만으로 반대편을 맞히지 않는다. 자기 collider·held gun·방패·벽·타깃의 layer/mask를 구분한다. state/effect 메시지의 shotId로 중복 피해와 중복 킬을 막는다.

‘킬 게이지’는 의미가 모호하므로 다음 기본안을 명시해 구현한다. 사용자의 후속 정의가 있으면 변경 가능하게 한다.
1. HP: 피격시 감소, 회복/리스폰시 증가. 예시 maxHP=100, 피해량/회복대기/리스폰시간은 설정 리소스.
2. Kill/Combo meter: 호스트가 확정한 상대 KO 때 증가, 자신의 KO 또는 명시한 무활동 시간 후 감소. HUD에 조건을 적고 무작위로 오르내리게 하지 않는다.

단순 hit toast, 누적 숫자와 실제 체력/게이지는 다르다. 게이지는 보간해서 표시하되 값의 권위는 호스트다. 피격·KO·복귀·보호시간·점수판·라운드 종료/재시작을 일관되게 만든다. 비유혈 놀이 표현, 짧은 복귀, 화면 흔들림 감소 설정을 기본으로 한다.

기존 방장 승인과 집/오피스 안전 구역은 유지한다. 허가 회수/구역 이탈/KO/저장 복원 후 무기 상태를 검증하고, 이미 대기 중인 발사도 무단 처리하지 않는다. 방패는 실제 정면/측후면 판정과 들기 애니메이션을 가진다.

## 9. 농구 — 게이지·스핀·스틸을 하나의 경기 루프로

`HELD`, `DRIBBLING`, `GATHER`, `SHOT_CHARGING`, `RELEASED`, `CONTESTED`, `LOOSE_BALL`을 구분하고 상태별 입력/손 점유/공 소유/물리를 정의한다.

이동 중 자연스러운 드리블, 패스/캐치, 왼손/오른손 전환, 슛 준비와 팔로스루를 실제 손/공 접촉 타이밍과 연결한다. 들고 달리는 위치 갱신이나 R을 눌러 공을 위아래로 흔드는 것만으로 경기 드리블을 완성하지 마라.

좌클릭 누르는 동안 **즉시 보이는 슛 게이지**가 차고, 릴리스 시 힘·타이밍/적정 범위·실패 피드백을 보여준다. 실제 release pose, 손 위치, 조준 방향, 거리, 점프/지상 상태와 힘으로 초기 속도를 정한다. 타이밍 판정은 호스트가 확인 가능한 input 순서/한계에 묶는다. UI charge를 거짓으로 보냈다고 초고속 슛이 되면 안 된다.

공에는 눈으로 식별 가능한 backspin을 주고, 해당 각속도가 물리 공에 반영되게 한다. 회전 텍스처만 움직이지 않는다. backspin이 모든 공을 넣어주는 것은 아니므로 입사각·반발·마찰·림 접촉과 함께 조정한다. 공기역학을 추가한다면 단위와 수치 안정성을 검증하고 꼭 필요한 모델만 사용한다.

스틸은 빈손의 가까운 상대가 타이밍을 맞춰 공을 노리는 행동이다. 예시 F=스틸, Q=공 패스/던지기, 좌클릭=슛이며 HUD로 안내한다. 손 뻗기/거리/각도/드리블 노출 구간/cooldown을 검증하고 성공 시 loose ball 또는 단일 소유 전환을 호스트가 판정한다. 멀리서 소유 ID를 바꾸거나 양쪽이 동시에 들지 않는다.

림의 실제 구멍, 백보드·고무/금속 접촉, 그물 시각 반응, 공의 반지름을 일치시킨다. 점수는 공 중심과 반지름을 고려해 위→아래 유효 통과를 1회 판정한다. 아래→위, 바깥쪽, 중복 packet, 오래된 shot, 지나치게 빠른 공을 시험한다.

자유 연습, 시간제 슈팅, 간단한 팀 경기의 팀 배정/점수/아웃/공 회수/종료/재시작을 완성한다. 2점/3점 등 실제 제공 규칙을 안내하고 공식 전 규칙 구현으로 과장하지 않는다. 은근한 자동 득점·시연용 속도 주입으로 사용자 플레이 시험을 대체하지 마라.

## 10. 축구 — 공을 손으로 들지 않아도 경기

기본 경기 흐름은 **공에 접근 → 발로 받기 → 이동에 맞춰 가벼운 터치 → 방향 전환 → 패스/슛 → 상대의 가로채기 → 루즈볼**이다. 기존처럼 손으로 들었다 내려놔야 킥이 되는 전제는 제거한다.

공은 자유 물리 물체로 두되 control radius, 발 touch interval, 제한된 impulse, 이동 속도, 회전 각도에 따른 유효한 제어를 구현한다. 발에 자석처럼 영구 부착하거나 벽 뒤 공을 끌어당기지 않는다. 달리면 터치가 길어지고 상대가 가로챌 여지를 둔다.

차는 발/ball contact를 애니메이션에 맞추고 짧은 패스와 충전 슛, 방향/높이, 골라인 통과, 골 후 킥오프, 경계 밖 복귀를 구현한다. 빈손 좌클릭=킥 충전/릴리스, 보조 버튼=짧은 패스, F=가로채기 같은 스포츠 입력을 명시한다. E/Q의 일반 사물 체계는 유지하되 경기 중의 손 집기는 경기 규칙에 맞게 차단하고 이유를 보인다. 자유 놀이에서는 E로 공을 집을 수 있다.

새로 배치한 축구공도 등록된 BallEntity로 처리하고 고정 ID `football` 한 개만 구현하지 마라. 경기 공과 소품 공을 구분해 경기 진행과 무한 생성이 충돌하지 않게 한다.

## 11. 디자인 — HOME / OFFICE / PLAY를 실제로 나누어라

전체 배치는 다음을 기본 방향으로 삼되, 정밀 평면/치수/동선은 실제 캐릭터와 검토해 확정한다. 숫자는 사용자가 지정한 사실이 아니라 설계값으로 표시한다.
```
공용 도착 로비 / 교실 안내
  ├─ OFFICE 업무동: 리셉션 → 주회의실 → 협업자료실 → 개인실 복도
  │                            └─ 방송실(방음·ON AIR)
  ├─ 연결 복도/중정/테라스
  ├─ HOME 주거동: 현관 → 거실 → 식당/주방/팬트리
  │                    └─ 실제 계단 → 침실/수면실/욕실/수납
  └─ PLAY: 승인된 게임·무기 공간 + 농구장 + 축구장 + 휴게 마당
```

같은 공간에 간판만 HOME/OFFICE 붙이지 않는다. 주거는 따뜻한 목재/천/가정 조명과 생활 크기, 오피스는 정돈된 업무 가구/스크린/읽기 좋은 조명/동선, 게임 구역은 방음·명확한 경계와 안전한 관전 영역을 갖춘다.

현관, 문틀·손잡이, 창틀, 천장·지붕, 계단/계단참·난간, 바닥 마감/걸레받이, 현실적인 가구 치수, 수납, 스위치, 욕실·주방 시설을 모델링한다. 계단의 실제 시작/끝 높이와 머리 여유/충돌을 검증한다. 외부는 괜찮은데 내부는 흰 상자라는 결과를 피한다.

각 핵심 공간에 완성 장면을 먼저 만들고 스타일을 적용하되 다른 필수 공간을 지우지 않는다. 사용자가 요청한 회의장 완성 샘플은 최우선 미술 검토 대상으로 한다. 보고서에는 실제 Godot 웹 화면의 동일 위치 before/after, 캐릭터 눈높이 스케일, 이동 영상과 렌더 성능을 제시한다. Blender 정지 렌더만 제출하지 않는다.

## 12. 최우선 회의실 — 실제 회의와 공동작업

회의실은 실제 테이블/좌석/모니터/보드/발표자 위치/자료 접근/읽기 가능한 시야와 음향을 가진다. 8인 이상 좌석의 초기 설계는 목표 정원과 함께 명시하고, 단순히 모니터와 책상 하나를 회의장이라고 하지 마라. 작업 중 총/마당 소리가 대화를 압도하지 않게 mixer/zone를 구성한다.

필수 흐름: 착석 → 의제 공유 → 자료 선택 → Docs 보고서 공동 작성 → Slides 자료 공동 수정/발표 → Excel 데이터/표 공동 작성 → 레이저와 보드 토론 → 질문/투표 → 결정/할 일 → 자료 참조/허용된 사본 저장.

### 12.1 실제 Google Docs/Google Slides/Excel

세 서비스는 각각 실제 공급자 원본에 연결한다. Yjs/Quill을 Google Docs라고, PDF를 Google Slides 편집이라고, HTML 표/Google Sheets를 Microsoft Excel이라고 표시하지 마라. Google Sheets는 사용자가 선택할 수 있는 추가 옵션이며 Excel을 몰래 대체하지 않는다.

`SharedDocumentRegistry`에 provider, 원본 document/file ID 또는 검증된 URL, 표시 이름, 편집/발표/보기 링크의 구분, room/meeting 연결을 둔다. 실제 접근 권한은 공급자의 공유 설정과 로그인에 따른다. 게임 방에 들어왔다는 사실만으로 Drive/OneDrive 편집 권한이 생기지 않는다.

초기 구현은 사용자가 이미 공유한 Docs/Slides/Excel Online 링크를 회의 세션에 등록하고 승인된 참여자가 같은 원본을 열어 공동 편집하는 완전한 동선을 제공한다. 계정 로그인을 수집/가로채지 않는다. 자동 문서 생성/가져오기/API 통합이 꼭 필요한 경우에만 공식 OAuth와 최소 scope를 별도 승인받아 추가한다. 서비스 계정 비밀키·쿠키·토큰을 게임/동료/저장 파일에 넣지 않는다.

Godot 안의 컴퓨터는 작업 패널의 실제 진입점이다. 공식적으로 지원되는 임베드는 기능/권한/브라우저별로 시험하고, 제한되면 명확히 표시한 원본 편집 탭/별도 창을 사용자 클릭으로 연다. 편집하지 못하는 게시용 iframe을 공동편집으로 속이지 마라. iframe 차단 헤더를 프록시로 제거하거나 브라우저 보안을 끄라고 요구하지 않는다.

‘원본 탭 열기’ 기본안이 게임 안 3D 화면의 완전한 내장 편집기와 동일한 것은 아니다. 요구 범위와 구현 가능한 방식·제약을 먼저 사용자에게 제시한다. 전체 Google/Excel 편집기 픽셀을 자동 3D 텍스처에 복사하거나 원격 키를 주입한다고 약속하지 않는다. 문서 자체의 실시간 협업은 공급자에게 맡기며, 게임은 자료 선택·발표 상태·세션 동선·권한 안내를 관리한다.

실제 두 계정이 같은 Docs 문단/Slides 슬라이드/Excel 셀을 편집하고 양쪽이 변경을 보는 시험을 수행한다. 한글 IME, 권한 없음, 세션 재입장, 링크 삭제, 학교 계정 외부공유 제한을 다룬다. 계정이 없어서 시험 못 한 것은 수동 미검증으로 남기고 ‘연동 완료’라고 하지 마라.

### 12.2 호스트가 문서 탭을 열어도 모두 멈추지 않게

현재 `visibilitychange → host frozen` 경로가 있다. Google Docs를 새 탭에 열면 이 경로를 밟을 수 있으므로 반드시 수정 설계를 다룬다. 단순히 frozen 한 줄을 지운다고 브라우저의 백그라운드 throttling 문제가 사라진다고 하지 마라.

가용한 정책을 검증하라: 같은 화면의 승인된 작업 overlay/나란히 열린 별도 창, 활동 중인 후임에게 명시적 host handoff, 또는 사용자가 승인한 지속 호스트. 실제 브라우저별 탭 전환 시 물리/음성/권한의 동작을 테스트한다. 모든 참가자가 문서만 보는 순간의 한계를 표시하고, 무단 유료 서버를 추가하지 않는다.

### 12.3 레이저·보드·회의 도구

레이저는 2D slideCanvas에서 포인터가 보이는 것과 3D 손에 든 장치가 작동하는 것을 구분한다. 장치 grip/muzzle에서 표면 ray → presentationSurface 로컬 좌표/UV → session/page/actor/sequence 검증 → 원격 red dot/beam 표시로 연결한다. 좌표 hardcode 대신 실제 화면 transform을 사용한다.

가로세로 여백/letterboxing, 화면 뒤/벽 가림, page 전환, presenter 이전, null/timeout, 불법 발표자의 포인터를 처리한다. 3D 스크린과 확대 보기에서 동일 점이 보이는지 호스트/참가자/늦은 입장자로 확인한다. 외부 원본 탭의 DOM 포인터를 권한 없이 추적하려 하지 않는다. 공유 화면을 발표하는 경우 해당 텍스처의 별도 좌표로 처리한다.

기존 화이트보드 실제 마카/펜촉, 확대 보드, 획/텍스트/색/굵기/지우개/Undo, 브레인스토밍 카드/그룹/투표, 마인드맵, 내장 공동 메모, 의제/타이머/손들기/질문 큐/회의 결과/할 일을 유지·완성한다. 단순히 ‘Google 링크 버튼’만 넣고 이 도구를 삭제하지 마라.

## 13. 컴퓨터·생활·수면·욕실

### 컴퓨터와 Google 검색
작업용 컴퓨터/키보드/마우스/의자와 모니터를 제대로 모델링한다. F 사용 → 확대 작업 UI → 검색어 입력 → 실제 Google 검색 → 자료 원본 열기 → 복귀의 흐름을 만든다. URL 인코딩과 https 검증, 팝업 차단 안내, 뒤로/닫기, 한국어 입력을 처리한다. 가짜 검색 결과를 만들어 보여주지 마라.

외부 사이트의 실제 임베드 허용을 확인하고 차단되면 새 탭/창을 정직하게 사용한다. 개인 검색어/계정/브라우저 히스토리를 다른 사람에게 자동 방송하지 않는다. 화면 공유는 명시적 선택과 브라우저 동의로만 하며, 타인의 컴퓨터를 보기만 해도 개인정보를 훔쳐보는 구조를 피한다.

### 3인칭 취침
F 침대 사용 → 접근/정렬 → 앉거나 몸 돌리기 → 눕기 → 베개/이불에 맞는 자세 → 호흡 정도의 sleep idle → 깨기 → 기립 애니메이션 → 안전한 바닥 복귀를 구현한다. 자기 화면은 이때 **3인칭**으로 바뀌어 자기 남자 캐릭터가 보이며, 벽/천장 camera collision을 처리한다. 깰 때 원래 1인칭으로 부드럽게 복귀한다.

수면 캐릭터 전체를 local_player라는 이유로 숨기지 마라. sleep view와 일반 1인칭 자기 머리 숨김을 별도 정책으로 둔다. 다른 사람도 같은 상태를 보고, 침대 점유·퇴장·복구·깨기 버튼·입력 잠금을 처리한다. 강제로 음성을 켜거나 세션 시간을 통째로 넘기지 않는다.

### 욕실/화장실
변기와 덮개/물내림, 세면대와 수도꼭지, 거울, 샤워 공간/수건/수납, 타일과 배수 위치, 문과 조명/환기 등을 실제 형태와 재질로 제작한다. 물내림/수도/등/문 같은 비노출 생활 상호작용을 제공한다. 거울은 웹 성능에 맞는 검증된 표현을 쓰며 무조건 실시간 반사 효과를 요구하지 않는다. 고정 설비를 구조물에서 뜯어 던지게 하지 않는 예외를 UI로 명확히 한다.

### 나머지 생활 유지
거실 자유 대화, 소파 앉기/눕기/점프, 냉장고 재료 → 조리 → 담기 → 식탁 운반 → 착석 식사 → 정리의 흐름을 보존한다. 아이템이 순간 삭제되고 메시지만 뜨지 않게 도구·음식·동작을 보인다. 수납/서랍, 책 읽기/던지기, 스탠드와 방 전체 스위치 회로를 실제 시각·소리·원격 상태·저장에 연결한다.

## 14. 공룡 러너 — 미로 대신 Chrome 오프라인 게임의 경험

기존 미로/픽맨 선택을 최종 기본 목록에서 제거하고 Chrome 오프라인 공룡 러너와 가까운 입력·시각·리듬을 제공한다. 작은 T-Rex형 공룡, 달리기/점프/웅크리기, 선인장/공중 장애물, 증가 속도, 점수/최고점, 충돌·게임오버·즉시 재시작과 선택적인 낮/밤 전환을 구현한다. 화분 피하기의 느슨한 유사 게임으로 요구를 다시 바꾸지 마라.

Chromium 공개 소스의 해당 게임을 재사용할 경우 정확한 commit, 코드·sprite·sound의 사용 조건/저작권/고지를 확인하고 필요한 범위만 포함한다. 또는 같은 핵심 경험을 자체 구현한다. 공식 Chrome 제품이라고 광고하거나 `chrome://dino`를 iframe에 넣는 방식에 의존하지 않는다. 다른 게임 코드의 출처 지시를 프로젝트 전체 실행 명령으로 신뢰하지 마라.

게임방의 실제 기계/화면에서 F로 시작, 다른 사람은 관전, Esc 종료 시 원래 캐릭터 시점 복귀. 입력이 FPS 이동/총에 전파되지 않게 한다. 해당 게임 자산을 로컬 번들로 제공해 페이지가 이미 로드된 상황의 네트워크 단절에도 게임이 불필요하게 멈추지 않게 검증한다. 전체 멀티플레이의 오프라인 보장을 의미하지 않는다.

## 15. 짧은 초대 코드와 고정 ‘교실’

### 15.1 일반 초대
기술 peerId/UUID를 그대로 보여주지 말고 `QEC-ETE` 같은 AAA-AAA 형식의 짧은 표시 코드를 제공한다. 대문자·하이픈 생략·공백 제거·붙여넣기를 정규화한다. 예시는 고정 모든 방의 코드가 아니라 형식이다. 동시 생성 충돌 검사, 만료/없는 방, 정원 초과, 잘못된 코드, 재접속 안내를 구현한다.

‘코드 복사’와 **‘초대 링크 복사’**를 별도 제공한다. 링크는 현재 배포 base path를 기준으로 실제 URL을 만들고, 예를 들어 `.../Friendslop_HomeOffice/?room=QEC-ETE`가 같은 세션으로 연결되게 한다. URL 예시는 구현 목표이며 아직 작동한다고 주장하지 않는다. 사용자의 명시적 참여/마이크 허가를 거친다.

짧은 공개 코드는 검색 편의이지 인증 비밀이 아니다. 초대 승인/학교 멤버십/교사 통제 등의 독립 권한 정책과 속도 제한을 둔다. 오래된 링크로 host/admin 권한을 얻지 못한다. UUID를 잘라 표시했지만 내부에서 여전히 그 잘린 peerId를 실제 방으로 찾는 반쪽 구현을 하지 마라.

### 15.2 고정 교실
시작 화면의 눈에 띄는 카드에 ‘교실’, 짧은 설명, 실제 확인 가능한 온라인/입장 상태, 입장 버튼을 둔다. 표시 이름은 **교실**, 내부 alias 예시는 `classroom`이다. `?room=classroom` 같은 **같은 고정 링크**로 반복 입장하며, 일반 무작위 세션과 섞이지 않는다.

다음 세 가지를 별개로 설계하고 문서·UI에 사실대로 표시한다.
1. 항상 같은 접속 주소/카드.
2. 현재 게임을 진행하는 권위 호스트.
3. 아무도 없거나 기기가 바뀐 뒤에도 남는 세계 데이터.

추가 비용 0원/브라우저 호스트 기본안에서는, 호스트가 있으면 그 세션에 합류하고 아무도 없으면 허용된 첫 입장자가 새 세션을 연다. 안전한 단일 호스트 선출/예약, 동시 입장 경합, readiness, 오래된 예약 회수, sessionEpoch, host handoff를 구현한다. 기존 export/import를 이용해 대표자가 저장 파일을 불러올 수 있고, 파일이 없다면 지정된 기본 교실이 열린다는 점을 안내한다. 이것을 무조건 마지막 상태의 자동 복원이라고 말하지 마라.

공유 rendezvous 저장소/상시 호스트가 필요한 구현이라면 사용하는 서비스, 접근 권한, 비용/한도, 기존 Firebase에 미치는 영향을 명확히 제시하고 별도 승인 후 적용한다. 영구 링크를 만들기 위해 무단 DB·Functions·TURN·서버를 추가하지 마라. 로컬 모의 rendezvous로 개발할 수는 있지만 실제 교실 동작 검증을 대신하지 않는다.

단순히 고정된 PeerJS ID를 먼저 선점한 사람을 교사/관리자로 인정하지 마라. 접속 발견·시뮬레이션 호스트·관리자 권한을 분리한다. 공개 교실 링크를 다른 사람이 선점/사칭하거나 새로고침 때 서로 다른 교실이 동시에 생기는 경우를 검증한다.

‘아무도 없어도 마지막 세계가 자동 보존되고 호스트 없이 언제든 실제 플레이 가능’까지 필요하면 추가 인프라와 비용·개인정보 설계가 필요함을 설명한다. 기존 무료 기본안을 몰래 이 요구의 완전 충족으로 대체하지 않는다. 실제 지원 정원/테스트 인원을 명시하고 학급 전체 무제한 접속을 약속하지 마라.

## 16. 음성·한국어 자막·방송실

### 통화
근거리 거리/방향 감쇠와 사용자 발화 범위·방장 상한, 문/벽/층간 감쇠, 전체 세션 모드를 유지·개선한다. 통화는 STT 실패와 독립적으로 작동한다. 마이크 장치/게인/입력 미터, PTT/열린 마이크/상대별 볼륨, echo/noise 제약의 실제 지원, mute/재연결/autoplay/장치 분리를 처리한다.

### 한국어 인식
현재 브라우저/온디바이스/Whisper 경로가 있다는 사실과 실제 학생 환경에서 잘 동작한다는 사실은 다르다. 어떤 제공자를 쓰는지, 한국어 언어팩 또는 모델 다운로드 상태, 처리 위치, 마이크 입력, VAD, 샘플레이트, 버퍼/백프레셔, 실패 이유를 보여준다.

사람이 말한 한국어 문장의 실제 원문과 비교한다. 이름·숫자·날짜·영문 혼합·회의 용어·짧은 말·잡음/두 사람 말 겹침을 포함해 조용한/잡음 있는 환경, 헤드셋/내장 마이크에서 시험한다. 기존 합성6문장 CER17.2%/WER29.7%를 품질 보장이나 실제 사람 성능으로 재인용하지 마라.

각 화자의 자기 마이크를 한 번 인식해 화자/utteranceId/sequence/generation/interim/final/권한 범위와 함께 전달한다. 중간→최종 교체, 중복/늦은 결과, 무음 hallucination, mute 뒤 결과 전송을 처리한다. 후처리로 의미·이름·숫자를 추측해 바꾸지 않는다. 모르는 단어는 원문 또는 불확실 표시를 유지한다.

동의된 충분한 한국어 테스트셋으로 CER/WER 정규화·p50/p95 확정 지연·실시간성·메모리·FPS 영향을 기록한다. 제안된 테스트 규모와 실제 수행 문장 수를 구분한다. 낮은 성능 기기에서는 명시적 자막 미지원/저성능 모드와 텍스트 대화를 제공하되 미구현을 완료로 부르지 않는다. 유료 API나 외부 음성 전송은 동의 없이 사용하지 않는다.

### 방송실
OFFICE 쪽에 방음된 방송실, 데스크 마이크/헤드셋, 콘솔/공지 화면, ON AIR 표시, 방송 시작/종료 버튼을 모델링한다. 방장/교사가 방송 권한을 부여하고 방송 중인 화자를 명확히 표시한다. 단순히 기존 전체음성 토글에 방송실이라는 이름만 붙이지 마라.

방송은 전체 세션 또는 승인된 구역으로 전달하며, 일반 주변 대화/게임 소리는 적절히 ducking한다. 전체 마이크 mute·상대 차단 등 사용자의 청취 선택을 몰래 무시하지 않는다. 여러 사람이 동시에 방송을 시작하면 잠금/대기/명시적 인계를 처리하고, 종료/강퇴/권한회수/host 이전 때 송신을 끊는다.

방송 자막은 ‘방송 · 화자’로 표시하고 같은 허용 범위를 따른다. 공지 텍스트를 함께 게시할 수 있으며 수동 공지는 저장 대상이다. 기본 원음 녹음은 하지 않는다. 방송 권한과 일반 global voice 권한을 공통 VoiceRouter에서 일관되게 관리한다.

## 18. 저장과 교실/외부 문서의 연결

`.homeworld` 버전 있는 단일 파일 내보내기/가져오기를 유지한다. 호스트의 일관된 확정 스냅샷에 건축 버전/세계 ID, 확장 개인실/슬롯, 가구/상자/책/램프·회로/문/음식 상태, 보드/내장문서/마인드맵/메모, 사용자 발표 자료, 합의된 게임 결과, 방송 공지, 일반 설정을 포함한다.

수면·손·좌석 점유·옛 네트워크 ID·방장 권한·킬 진행 중 effect·무기 허가는 새 세션에서 안전하게 초기화한다. 저장에 움직이는 물리를 raw 엔진 메모리로 dump하지 말고 안정된 의미 상태로 정한다. 새 포맷은 이전 파일 migration/거절/백업 정책을 제공한다.

Google/Excel 원본은 공급자가 보존한다. 저장 파일은 검증된 문서 참조와 사용자가 허용해 만든 사본을 구분한다. URL 저장만으로 원본 내용 전체가 오프라인 백업되었다고 표시하지 않는다. 토큰·비밀번호·개인 검색 이력·동의 없는 원음/STT는 제외한다. 링크에 민감한 공유 권한이 포함될 수 있으므로 공유 대상과 외부 파일 접근 범위를 안내한다.

모든 참가자가 나가기 전에 대표자가 내보내고 다음 날 가져오는 흐름은 그대로다. 교실의 고정 링크와 마지막 파일 복원은 독립적으로 표시한다. 다른 기기에서 원본 문서 권한이 없거나 로컬 복구본이 없으면 그 사실을 분명히 안내한다.

파일의 버전/크기/압축 폭탄/경로 탈출/중복 ID/유한 수치/참조/asset allowlist/checksum을 검증하고 임의 script/Resource 실행을 금지한다. 실패한 가져오기로 현재 세계를 잃지 않는다. 브라우저 다운로드 요청과 실제 파일 보관 완료를 구분하고 beforeunload 보장에 의존하지 않는다.

## 19. 성능·네트워크·보안 기준

지원 버전의 Godot/GDScript/Compatibility 웹 빌드를 먼저 고정한다. STT/화면 공유/실시간 음향을 모두 켠 경우를 별도로 측정한다. 이 프로젝트에 있는 큰 WASM/ONNX/STT 파일들을 첫 입장에 무조건 로드하지 마라. 3D 세부 묘사는 LOD/가시성/재질/텍스처/충돌체/동적 조명/rigid body sleep으로 최적화하고 집을 흰 상자로 되돌리지 않는다.

host inputs/authoritative physics와 client render interpolation을 분리한다. state를 매번 모든 사물의 전체 JSON으로 전송하는 현 구조의 바이트/빈도를 측정하고 delta/interest management/확정 이벤트를 설계하라. 변화 없는 모든 정적 가구를 고빈도 반복하지 않는다. 자료 파일과 STT 모델 다운로드가 음성/게임 패킷 큐를 점유하지 않게 한다.

동일 PC8개 브라우저의 과거 낮은 FPS를 분산8인 성능처럼 표시하지 않는다. 한 노트북/독립기기 2·4·8인 각각의 사양, WebGL backend, 해상도, FPS/frame time p50/p95, 통신량, active bodies, 메모리/누수, 통화 품질을 보고한다. 목표치는 측정할 설계값이며 성공보장 수치가 아니다.

짧은 코드·고정 교실의 brute-force/사칭/권한 도용/스팸을 다루고, 사용자 입력 HTML/임의 URL/P2P payload의 크기/타입/속도를 제한한다. 승인된 학교 소규모 호스트 모델은 상용 안티치트/불신 호스트로부터의 완벽한 비밀 보호와 다르다. 음성/STT/외부 문서의 실제 신뢰 경계를 설명한다.

## 21. 실행 순서와 산출물

1. 읽기 전용 진단과 버전/실패 재현. 기존 상태를 보존한다. GLB·MCP·도구·브라우저 접근 상태를 확인한다.

3. 런타임 생성 로직/입력/권위를 구조화하며 Blender 리깅·애니메이션, 물리 검증장과 프로필을 병행한다.
4. 가장 중요한 회의실과 HOME/OFFICE 평면을 확정하고, 실제 Docs/Slides/Excel·레이저·컴퓨터·호스트 탭 문제를 수리한다.
5. 총/HP/킬게이지, 농구/스틸/스핀, 축구/발드리블, 생활/욕실/3인칭수면, 공룡게임을 완성한다.
6. 교실 고정 입장·짧은 코드/URL, 방송실/한국어 자막, 전체 저장/복구를 통합한다. 기초 네트워크/권한 설계는 앞 단계부터 반영한다.
7. G01~G16과 승계 요구 전수 상태를 확인하고, 재현 가능한 빌드/테스트/배포 명령과 증거를 제공한다.

각 수정은 원인·변경 코드·회귀 시험·실행 증거를 동반한다. 사진 몇 장과 ‘기능완료’라는 말로 끝내지 마라. Godot 프로젝트/씬/스크립트, 실제 GLB/애니메이션과 .blend/제작스크립트, 역할 명확한 JS 모듈, 저장 migration, 시험 fixture, 배포 manifest, 한국어 안내와 라이선스를 남긴다.

최종 보고 형식:
- 현재 커밋/배포 버전/실제 실행한 환경.
- 사용자 증상별 root cause(확인/미확정 구분)와 수정 경로.
- R01~R30, 이전 요구 승계, G01~G16 상태와 증거.
- 남자 GLB/애니메이션의 실제 연결 상태.
- 회의 서비스 연동에서 실제 2계정으로 검증한 범위.
- 초대/교실에서 항상 되는 부분과 호스트/저장에 의존하는 부분.
- 실행·빌드·수동 테스트 명령, 변경/생성 파일.
- 미완료/제약/승인 필요 인프라. 구현하지 않은 기능을 옵션으로 삭제하지 않음.

성공 기준은 ‘기능을 넣을 수 있는 기본 구조’가 아니다. **친구가 서로 보이고, 실제 회의를 하고, E/Q로 물건을 다루고, 자연스럽게 공과 총으로 놀고, 집에서 쉬며, 고정 교실로 다시 모여 저장한 작업을 이어가는 경험**이다.

### 3. 수정 우선순위

P0: 배포 재현성과 실제 서로 보이는 2~3인 네트워크. P1: 입력/권위/애니메이션/물리의 작은 단위 회귀를 지키며 구조 정리. P2: 최우선 제품 기능인 회의실·실제 협업 서비스·레이저·교실 입장. P3: 총/체력/킬, 농구, 축구와 생활·공간 마감. 음성/방송과 저장은 모든 단계에서 통합 검증한다. 일정상 병렬 가능하지만 서로 보이지 않는 빌드를 완성본으로 제출하지 않는다.

### 4. 반드시 구분할 제품 선택

- HP(피격시 감소·회복/리스폰시 증가)와 킬/콤보 게이지(킬시 증가·정의한 조건에서 감소)는 별개다. 사용자의 ‘킬 게이지’ 의미를 임의로 하나로 덮지 않고 기본안을 명시한다.
- 무제한 사격은 허가된 놀이 공간의 자유사격이다. 기존 방장 승인 요구를 유지하되 허가 후 ready 단계에 갇히거나 재장전 안내 없이 막히게 하지 않는다.
- 영구 교실 링크, 현재 시뮬레이션 호스트, 월드 영구 보존은 서로 다르다. 정적 Pages만으로 세 가지가 자동 완성되지는 않는다.
- Google Docs/Slides와 Excel은 실제 서비스 원본 공동 편집을 요구한다. Yjs/Quill이나 PDF 뷰어를 Google/Excel 기능이라고 바꿔 부르지 않는다.
- Google 검색 결과·실제 편집기를 iframe/3D 텍스처로 자유롭게 넣을 수 있다고 보장하지 않는다. 공식 허용 임베드·안전한 원본 탭·명시적 화면 공유를 구분한다.
- Chrome 공룡 러너가 기존 미로/픽맨 최종 요구를 대체한다. chrome://dino 내부 주소를 iframe으로 연결하는 것이 아니라 라이선스 확인한 코드/자산 또는 동등한 자체 구현을 배포한다.
